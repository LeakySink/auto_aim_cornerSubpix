# 物理世界假设清单

> 本项目的每一行算法都建立在下列假设之上。**假设被违反时，不会报错，只会"打得不准"。**
> 因此每条都给出：**代码位置 / 违反后的表现 / 如何验证**。排查"莫名不准"时按表逐条对号。
>
> 最后更新：2026-10（随 `docs/architecture.md` 附录 C 同步）

## B. 运动学（EKF 模型假设）

| # | 假设 | 代码位置 | 违反后的表现 | 如何验证 |
|---|---|---|---|---|
| B1 | 平移**匀速**（CV 模型），加速度仅作白噪声 | `target.cpp` 的 `F` 矩阵（位置只由速度积分） | 加速/急停时相位滞后、超调 | 让目标加减速，看 `target_vx` 跟随延迟 |
| B2 | 旋转**匀速**（`a += w·dt`），角加速度作白噪声 | 同上 | 变速旋转时 `a`/`w` 抖动 | 变速转动，看 `w` 是否平滑 |
| B3 | `r`（半径）/`l`（侧板偏移）/`h`（高度偏移）**恒定**（Q 中无过程噪声） | `target.cpp` 的 `Q` 矩阵 | 它们会吸收观测误差 → 相位更不稳、瞄点漂 | 长跑后看 `r` 是否偏离 yaml 半径 |
| B4 | 同一时刻只观测到**一块板** | `target.cpp:update()`（单块 armor 更新） | 多板同时可见时只用其中一块，信息浪费 | 多板可见场景下对比只用单板 vs 多板融合 |
| B5 | 目标不瞬移（数据关联可用空间门控） | `tracker.cpp` 空间门控（`1.0 + 0.2·dist`） | 串目标、EKF 被拉跑 | 两个同类目标相邻时观察是否串号 |
| B6 | 观测噪声零均值、近似高斯 | `target.cpp` `R_dig` 构造 | NIS 长期超标（`nis > 9.488`） | Watch 页看 `nis` 与 `nis_threshold` 参考线 |

## G. 最脆弱的 5 条（优先验证顺序）

1. **C2 运动模糊/卷帘**：旋转 10 rad/s × 10 ms 曝光 → 板面拖影 ≈ 0.1 rad，可能单独就足以让关键点偏半个板宽。**先测这个**，它可能解释"旋转靶抖动"的另一半原因。
2. **E1 弹速恒定**：连发掉速未标定 → 远距离系统性偏低。
3. **E5 发射延迟**：`0.065/0.055 s` 是估的还是测的？脉冲响应一测即知。
4. **A1 几何尺寸**：1 月最可能变，必须配置化（见 `docs/roadmap.md` W3–W4）。
5. **B1/B2 匀速假设**：真实目标会加减速、会突然反向转。
