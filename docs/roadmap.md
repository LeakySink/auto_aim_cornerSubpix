# 后端加固路线图（2026-10 ~ 2027-01）

> 背景：新装甲板样式预计 **2027-01 中旬** 发布，届时需要重训 YOLO、重做关键点定义、
> 调整前端可视化。在此之前，检测侧的工作无法定稿。本文件规划这 10 周内如何把
> **与装甲板外观无关的部分** 做到工程上限，使 1 月的切换成本从"改代码+调参+肉眼验证"
> 压缩到"换适配层 + 跑评测台"。

## 0. 变更影响矩阵

| 大概率会变（1 月） | 大概率不变（现在就能做到极致） |
|---|---|
| 装甲板外观：灯条排布/数量、贴纸纹样、数字字体、颜色分区 | **几何**：RM 规则的板宽（135/230 mm）、灯条长（56 mm）、车体半径/板数（4/3） |
| 关键点定义与类别表、训练数据、模型输入尺寸 | **运动学**：目标绕竖直轴匀速转、平移基本匀速 |
| 前端可视化标签、调试图层 | **弹道物理**：g、二次阻力、22 m/s 初速、发射延迟 |
| 检测侧阈值/后处理/NMS | **标定链**：相机内参、相机-云台外参、云台零位 |
| | **系统**：16.7 ms 预算、线程模型、CAN/相机链路、日志回放 |

**核心策略**：把「外观」收敛成可替换的适配层（detector 实现 + 关键点语义 + 标签表），
把「几何 / 运动学 / 弹道 / 时延 / 系统」做成硬资产。判断标准：**1 月除新增一个
detector 实现和改 yaml 外，不应改动任何后端文件。**

## 1. 十周计划

### W1–W2：评测台（最高优先级）

没有评测就没有改进；1 月能否一天判定新模型，全看这一项。

| 项 | 内容 |
|---|---|
| 目标 | `.rlog` 离线回放 + 分桶指标输出 |
| 交付 | `tests/eval/replay.cpp`（读 RLG2 → 驱动 Camera→Detector→Solver→Tracker）、`tests/eval/metrics.cpp`、`run_eval.sh`、真值采集规范 |
| 指标 | 检出率 `P_n`、关键点误差（有标注时）、**PnP 距离误差**（卷尺真值）、角度误差、EKF 收敛时间、丢目标率、瞄点误差、开火判定正确率；全部按 **距离 / 角度 / 亮度** 分桶 |
| 验收 | 60 s 回放 < 30 s（≥2× 实时）；同一 rlog 两次跑结果一致（可复现）；报告为 CSV + markdown |
| **现状** | **Stage 1 已完成（2026-10）**：`python -m rdbg metrics/csv <run.rlog>` 可对录制数据出逐帧报告（关联 id 推进 / 相位斜率与抖动 / w 过零 / nis 越限 / 观测-估计一致性 / 距离-角度分桶），纯标准库、无需实车；自测见 `tests/eval/check_metrics.py`（合成 good/bad 两种场景）。**Stage 2（重跑检测，用于评估新模型）待做**：需在 C++ 侧实现 `.rlog` 读取 → 驱动 Detector→Solver→Tracker |

> 附带收益：现场问题（如"红框乱飘"）从此可离线复现，不必赌现场。

### W3–W4：接口解耦（让 1 月只改配置）

| 项 | 内容 |
|---|---|
| 目标 | 检测器可插拔；装甲板几何与关键点语义全部配置化 |
| 交付 | `IDetector` 接口（`detect(img) → vector<Detection{box, keypoints, cls, score}>`）；`ArmorGeometry` yaml 段（板宽/灯条长/倾角/物体点顺序/关键点个数）；**关键点语义校验器**（凸性、对边长比、顺序 TL,TR,BR,BL、镜像一致性） |
| 现状 | `solver.cpp` 里 `SMALL_ARMOR_WIDTH/BIG_ARMOR_WIDTH/LIGHTBAR_LENGTH` 与 ±15° 倾斜仍是硬编码；车体几何（radius/armor_num）**已在 yaml**（`ekf.{normal,outpost,base}`，0.2/4、0.2765/3、0.3205/3） |
| 验收 | 新增一个 detector 实现只需新增文件 + yaml，不改任何现有 `.cpp/.hpp`；关键点顺序接错时启动即报错 |

### W5–W6：状态估计鲁棒化（完全不依赖外观）

| 项 | 内容 |
|---|---|
| 目标 | 旋转目标不抖、多目标不串、时延被补偿 |
| 交付 | ① 旋转：±π 几何消歧（**已完成**）+ 多帧相位回归估 `w` + 侧向板（`|cos armor_yaw|` 小）距离观测降权；② 多目标：马氏距离门控 + 匈牙利匹配 + 优先级；③ **端到端时延标定**（曝光→检测→解算→CAN→云台到位→出膛），纳入预测 |
| 验收 | 10 rad/s 旋转靶：`armor_id` 正常 0→1→2→3 推进；`w` 估计误差 < 10%；5 m 处瞄点抖动 < 0.1° |

### W7–W8：弹道与控制

| 项 | 内容 |
|---|---|
| 目标 | 弹道参数为实测值；开火判定按板面尺寸 |
| 交付 | 连发掉速曲线实测（第 1/5/10 发）；弹道表覆盖扩展到实测最大距离；云台动力学辨识（一阶惯性 + 纯延迟）→ MPC 参考轨迹与限幅重设；**开火判定改造**：弹道误差投影到板面并与板尺寸比较（现为固定 `fire_thresh: 0.15`） |
| 验收 | 5 / 8 / 12 m 静态靶命中率 > 90%；移动靶（匀速 2 m/s）命中率 > 60% |

### W9–W10：系统级加固

| 项 | 内容 |
|---|---|
| 目标 | 长时间稳定、故障可恢复、性能可解释 |
| 交付 | 30 min 长跑；故障注入（拔相机 / 丢 CAN / 断电重启）；各阶段耗时剖析（锁定 16.7 ms 预算）；**启动自检**（相机/云台/CAN/模型/标定文件一键体检）；`docs/architecture.md` 回填 |
| 验收 | 30 min 无崩溃、RSS 增长 < 10 MB；单帧耗时 P99 < 16.7 ms；自检能在 3 s 内报出缺失项 |

## 2. 1 月窗口（预计 3–5 天）

1. 新模型训练 / 导出（ONNX → OpenVINO / RKNN），**用 W1–W2 的评测台做验收**；
2. 若规则改了板宽/灯条尺寸 → 只改 `ArmorGeometry` yaml；
3. 关键点顺序/语义若变 → 只改适配层 + 校验器参数；
4. 前端标签与图层适配；
5. 回归：`run_eval.sh` 对比 v_old / v_new，出报告。

## 3. 总验收标准（1 月前必须全部达标）

| 维度 | 指标 |
|---|---|
| 感知鲁棒性 | 5–12 m、±45° 偏航、室内正常光照下：`P_n` ≥ 0.9、PnP 距离误差 ≤ 0.3 m |
| 状态估计 | 旋转 10 rad/s 时 `w` 误差 < 10%，丢目标重捕 < 200 ms |
| 弹道 | 静态靶命中率 > 90%（5/8/12 m） |
| 时延 | 端到端延迟测量误差 < 3 ms，且已被补偿 |
| 系统 | 30 min 无崩溃；单帧 P99 < 16.7 ms |

## 4. 依赖与风险

- **依赖硬件**：需要能测弹速（高速相机或测速靶）、能固定标定靶、能录制 rlog；
- **风险**：① 1 月若规则改了板宽/灯条长度，几何层要重标（有配置化后可 1 天完成）；
  ② 若新装甲板外观导致关键点定义从 4 点变 6 点，适配层需支持可变关键点数（W3–W4 的校验器要预留）；
  ③ 评测台依赖 rlog 的图片完整性，需确认录制时不丢帧。
